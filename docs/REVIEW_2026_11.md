# November 2026 review and verification

Review date: November 3, 2026. Scope: the existing agency sales demo, with product,
backend, security and UX reviews. The [PM decision memo](PRODUCT_REVIEW.md) records
the acceptance criteria and deferred work.

## Correctness and reliability fixes

- ERP exports now use reviewed arithmetic checks and the human approval timestamp.
  Original extraction, model evidence and original checks remain immutable.
- Evidence from selected PDF pages maps back to physical source pages. Invalid
  references require review; incomplete page coverage remains inconclusive after review.
- Decimal verification supports extreme schema-valid quantities and 500-line sums.
- Impossible Groq capacity settings fail visibly before inference. Transient worker
  database failures retry safely; cleanup logs exclude exception contents.
- The UI rejects stale workspace responses, serializes polling, reuses upload retry
  keys and exposes pending reviews beyond the latest 100 document-register records.
- Reviewers can compare original and reviewed records. Changed values say “Reviewed”
  and citations explicitly identify the original extraction. Source navigation,
  connection recovery, validation feedback and mobile layouts were improved.

## Security changes

- Anonymous workspace creation has hourly, daily and total bounds; returning guests
  remain usable. Concurrent guest admissions and usage counters are serialized.
- Malformed bearer tokens return 401. All requests have streamed body limits;
  rejected requests retain protective headers and safe errors retain Retry-After.
- Native PDF/image inspection, text extraction and rendering run in bounded child
  processes. Tests exercise real PDFs/images, timeout kill/reap, capacity contention,
  native crash responses, malformed output and stripped environment credentials.
- The child uses a fixed interpreter/script without a shell. Defaults are one slot
  per application process, 15-second wall timeout, 10-second CPU limit, 16 MiB output
  and Linux 256 MiB address space. macOS does not enforce the address-space ceiling.
- Exhausted guest allowances are rejected before native parsing. Busy previews can
  retry; a busy worker requeues before calling a provider.
- Updated Pillow, certifi, Vite and source-map-js to patched releases. Both lockfile
  audits report no known vulnerabilities as of this review.

Bandit reports three reviewed LOW findings: the explicit rejection of the insecure
local token, importing subprocess, and the fixed no-shell parser invocation. This
review does not establish that no vulnerabilities exist. Resource limits are not
an operating-system security sandbox or a DDoS protection service.

## Release gates and operating limits

Ubuntu CI must pass real-document tests under Linux resource limits before the
Render deployment. Then verify deployed readiness, guest isolation, page previews,
review/ERP behavior and the public launch link. Publication results are recorded
after those checks rather than inferred from local success.

The [new launch link](https://yashmodi1804.github.io/folio-invoice-verification/launch/)
waits up to 90 seconds for readiness and always offers the static sample walkthrough.
It does not disable Render sleep. The recorded free-database expiry is November 6;
no paid service or permanent-storage promise was introduced.

Unverified: client-document extraction accuracy, multi-worker quota coordination,
high-volume traffic, backups/restore and legal compliance. Guest credentials identify
a browser, not a person. Physical upload cleanup runs while the service is awake;
it does not erase copies held by upstream providers. Proprietary redistribution
also requires a project/dependency licensing decision; see the PM memo.
